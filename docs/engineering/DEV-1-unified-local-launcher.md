# DEV-1 — Unified local launcher

Run `./scripts/start-dev.ps1` from the Windows repository root (PowerShell). Stop with `./scripts/stop-dev.ps1`.

## First-time prerequisites

- Ubuntu SSH alias `samskara` works noninteractively using an unlocked SSH agent. If `ssh -o BatchMode=yes samskara true` fails, unlock your key with `ssh-add` first.
- Ubuntu has the same current agent code as Windows, a functioning `.venv` with FastAPI/Uvicorn, an existing Enforcer binary, and a disposable `a7-demo/workspace/calculator/calculator.py` fixture.
- Windows has `ollama`, Qwen `qwen3.5:4b`, Node.js, npm, and installed `ui/node_modules`.
- SSH server permits loopback-only local and remote port forwarding. Windows ports 5173 and 8765 and Ubuntu port 11434 must be free. A preexisting Ollama server on Windows port 11434 is allowed.

## Security and limitations

- Local-only: the API and UI bind to loopback, and SSH forwards are private. **Do not publish this dev server to Hugging Face Spaces or the internet.**
- Vite injects the API token on its **server-side proxy**, not into browser JavaScript. No `VITE_SWE_OPERATOR_TOKEN` is needed. Browser requests go to same-origin `/api`.
- The launcher generates a fresh token per session and transmits it to Ubuntu over SSH stdin. It is not written into project files. The token still exists in process environments and can be read by sufficiently privileged local processes.
- The launcher does not alter the Rust Enforcer, Git credentials, approval rules, or the production backend. Live mode remains **read-only proposal generation**.
- The launcher does not install packages, start the VM, or resolve an SSH key passphrase. It checks prerequisites and fails with an actionable message.
- Stop script only targets recorded Windows process IDs and the recorded Ubuntu API PID; it does not kill unrelated processes intentionally. Review processes before using it on a shared development host.
- The Windows frontend needs `ui/vite.config.ts` and `ui/src/liveApi.ts` from this patch. Do not store a token in a `VITE_*` variable.

## Verification

1. Run `./scripts/start-dev.ps1` in Windows PowerShell.
2. Open `http://127.0.0.1:5173` and confirm the UI does not show an authentication error.
3. Submit a subtraction analysis task. Confirm the proposal is generated by Qwen via the existing Enforcer.
4. Run `./scripts/stop-dev.ps1`. Confirm the launcher-owned ports are released.

## Troubleshooting

- SSH key asks for passphrase: start Windows OpenSSH agent and `ssh-add` your key.
- Ollama model missing: `ollama list` and `ollama pull qwen3.5:4b` as appropriate.
- Ubuntu API fails: inspect `~/secure-swe-agent/.dev-api.log` (do not paste credentials).
- Port occupied: stop old tunnels or services before launching.
- The CLI and backend still need the same synchronized agent code; the launcher does not transfer source files.
