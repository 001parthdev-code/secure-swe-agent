# R4.3 — Git commit approval binding and recovery review

## Finding and correction

Before R4.3, A5 commit approvals were SHA-256 digests of only the staged textual diff. Identical diffs in a different task branch, repository, or HEAD could share a fingerprint. The operator-reviewed context was therefore not fully bound to the commit approval. The trusted broker now hashes a canonical JSON record of the resolved repository root, task branch, current HEAD, relative file path, and staged diff. The existing 64-character fingerprint API is unchanged, but fingerprints generated by older versions are deliberately invalidated. Always run `review-commit` again after upgrading.

## Regression coverage

New tests verify that an approval from one task branch cannot be replayed on another branch with an identical diff, cannot be replayed in a different repository, and becomes stale after HEAD changes while the staged patch remains the same. The existing staged-change and approval tests continue to pass.

## Recovery boundary review

The SQLite journal enforces state transitions with revision checks. An expired owner is not automatically stolen; operator quarantine requires explicit termination confirmation, and reconciliation is not an automatic replay. The journal records approval digests but does **not** independently verify their semantic binding; trusted A7 broker operations must perform that validation. The operator confirmation flag is an assertion, not independently verified process-termination evidence. The experimental FastAPI task dictionary is in-memory and is not covered by journal durability.

## Remaining threat assumptions

The CLI is intended for trusted, operator-controlled Git repositories and configuration. The approval digest is a consistency fingerprint, not a cryptographic signature or a substitute for operator identity. The repository path can be reused or replaced by a privileged local actor; protection against a malicious operator, malicious Git configuration, or hostile local filesystem is out of scope for this prototype. The frozen Rust Enforcer was not changed or re-audited in this increment.

## Verification

In the patch preparation environment, `python -m unittest discover -s agent/tests -q` passed 91 tests and `python -m compileall -q agent` succeeded. Windows and GitHub Actions remain required release gates.
